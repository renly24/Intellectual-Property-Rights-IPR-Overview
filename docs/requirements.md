# 要件定義書：知的財産権（著作権）学習Webアプリ

> ステータス：ドラフト v0.1（要件ヒアリング結果のまとめ）

## 1. 目的

高校「情報Ⅰ」の **大学入学共通テスト対策** として、著作権を中心とした知的財産権を学ぶ。
解説を「読むだけ」で終わらせず、**生徒が頭と手を動かしながら** 理解・定着できる教材にする。

## 2. 利用者と利用場面

| 項目 | 内容 |
|---|---|
| 主な利用者 | 高校生（情報Ⅰ履修者、共通テスト受験予定者） |
| 利用場面 | 授業中、1人1台端末（タブレット／PC）で使用 |
| 想定端末 | iPad・Chromebook など。**タッチ操作を最優先**、マウス操作にも対応 |
| 1章の長さ | 約10〜15分（授業の導入・まとめに組み込める単位） |
| 教員向け機能 | 不要（生徒用機能のみ） |

## 3. 学習範囲

**著作権を中心に厚く、周辺分野は軽く** 扱う。

### 章構成案

| # | 章タイトル | 主な内容 | 主な操作 |
|---|---|---|---|
| 1 | 知的財産権の全体像 | 産業財産権と著作権の違い、方式主義／無方式主義 | ドラッグ仕分け |
| 2 | 著作物とは何か | 「思想又は感情を創作的に表現したもの」、著作物に当たらない例 | スワイプ判定 |
| 3 | 著作者の権利 | 著作者人格権（公表権・氏名表示権・同一性保持権）と著作財産権（複製権・公衆送信権など） | ドラッグ仕分け |
| 4 | 著作隣接権と保護期間 | 実演家・レコード製作者・放送事業者等、保護期間（原則 死後70年） | ドラッグ仕分け＋選択 |
| 5 | 許諾なく使える場合 | 私的使用のための複製、引用の要件（第32条）、非営利・無料の上演等 | 文中タップ指摘 |
| 6 | 学校での利用 | 教育機関での複製等（第35条）、授業目的公衆送信補償金制度 | スワイプ判定 |
| 7 | SNS・動画投稿と著作権 | スクショ投稿、切り抜き動画、「歌ってみた」、違法ダウンロード | スワイプ判定＋文中タップ |
| 8 | 生成AIと著作権 | AI学習と第30条の4、AI生成物の利用時の注意 | スワイプ判定＋文中タップ |
| 9 | 周辺の権利 | クリエイティブ・コモンズ、産業財産権4法（特許・実用新案・意匠・商標）の概要、肖像権・パブリシティ権 | ドラッグ仕分け |
| 10 | 総合演習（共通テスト形式） | 会話文・資料を読んで答える問題 | 選択＋各操作の混合 |

## 4. 学習体験の設計

### 4.1 1章の流れ

1. **導入の問い** — 身近な場面から「これって大丈夫？」と予想させる
2. **解説（短い段落）** — 数段落ごとに小問を挟み、答えると続きが開く
3. **操作問題** — 下記の操作形式を章ごとに組み合わせる
4. **まとめ** — 要点の確認と、間違えた問題の振り返り

### 4.2 操作形式（タップのみの単調さを避ける）

| 形式 | 操作 | 例 |
|---|---|---|
| ドラッグ仕分け | カードを指で箱へ運ぶ | 「公表権」「複製権」を人格権／財産権の箱へ |
| スワイプ判定 | 事例カードを左右にスワイプ（OK／NG） | 「文化祭で無料・無報酬の演奏」→ OK？ NG？ 判定後に根拠条文を解説 |
| 文中タップ指摘 | 文章中の問題箇所をタップ | 生徒のブログ記事から「引用の要件を満たしていない箇所」を指摘 |
| 選択問題 | 大きなボタンで選ぶ | 共通テストのマーク式に近い形式（総合演習中心） |

- すべての操作に **タップだけで代替できる手段** を用意する（ドラッグが苦手な場合・アクセシビリティ対応）
- 回答後は必ず **理由・根拠の解説** を表示する

## 5. 機能要件

| ID | 機能 | 内容 |
|---|---|---|
| F-1 | 章一覧 | 章ごとの完了状況・正答率を表示 |
| F-2 | 章の学習 | 4.1 の流れで進む。途中から再開可能 |
| F-3 | 操作問題 | 4.2 の各形式の問題コンポーネント |
| F-4 | 解説表示 | 回答ごとに正誤と根拠を表示 |
| F-5 | 進捗保存 | ブラウザ（localStorage）に完了章・正答率・間違えた問題を保存。ログイン不要 |
| F-6 | 復習 | 間違えた問題だけを解き直す |
| F-7 | 進捗リセット | 共有端末向けに学習記録を消去できる |

## 6. 非機能要件

| 項目 | 内容 |
|---|---|
| 形態 | 静的Webアプリ（サーバー不要） |
| 技術構成 | 6.1 のとおり、ほかの edu 系教材リポジトリにそろえる |
| 公開 | GitHub Pages と FTP サーバー（6.2） |
| コンテンツ管理 | 解説・問題は JSON 等のデータファイルに分離し、コード変更なしで追加・修正できる |
| 画面構成 | モックのとおり「章一覧 → 解説 → 操作問題 → まとめ」（ほかの教材のスライド形式にはしない）。部品とテーマは MUI でほかの教材に寄せる |
| デザイン | 落ち着いた教材風（白基調・読みやすい文字・重要語のみ色付け） |
| 操作性 | タッチ対象は十分な大きさ（目安 44px 以上）、横向き・縦向きの両方に対応 |
| 個人情報 | 収集しない。データは端末内のみに保存 |

### 6.1 技術スタック

参考：`renly24/edu-public-key-simulator`、`renly24/edu-symmetric-key-simulator` ほか

| 項目 | 採用 |
|---|---|
| フレームワーク | Next.js 16.2.6（App Router、`output: "export"`、`distDir: "out"`） |
| UI | React 19.2.4、MUI v7（`@mui/material`、`@mui/icons-material`、`@mui/material-nextjs`、Emotion） |
| 言語 | TypeScript |
| Lint・整形 | ESLint 9（`eslint-config-next`）、Prettier |
| E2E テスト | Playwright。**デスクトップ（マウス）と iPad（タッチ）** の両方で、全章を最初から最後まで操作する |
| Node.js | 20 |

`next.config.ts` は `basePath` と `assetPrefix` を環境変数 `NEXT_PUBLIC_BASE_PATH` から読む（公開先ごとにルートフォルダーが違うため）。

### 6.2 CI/CD（GitHub Actions）

| ワークフロー | タイミング | 内容 |
|---|---|---|
| `e2e.yml` | PR、`main` への push | ビルドして Playwright E2E（chromium・webkit）を実行し、レポートを保存する |
| `deploy.yml` | `main` への push | `NEXT_PUBLIC_BASE_PATH=/Intellectual-Property-Rights-IPR-Overview` でビルドし、GitHub Pages へ公開する |
| `deploy-ftp.yml` | `main` への push | 共通ワークフロー `renly24/edu-deploy-workflows/.github/workflows/ftp-deploy.yml@main` を `secrets: inherit` で呼ぶ。`project-dir: edu-copyright` |

- FTP の公開 URL：`http://e.gmobb.jp/omaesensei/digital/edu-copyright/`
- リポジトリ Secrets に `FTP_HOST`・`FTP_USER`・`FTP_PASS` の登録が必要（`edu-deploy-workflows` の「Sync FTP secrets」でコピーできる）
- GitHub Pages は Settings → Pages の Source を「GitHub Actions」にする
- 教材一覧ページ（`digital/index.html`）へのリンク追加は手作業

## 7. コンテンツ作成方針

- 解説・問題は Claude が著作権法の条文・文化庁の資料に沿って下書きし、**オーナーが内容の正確さを確認** する
- 法改正の影響を受ける記述（保護期間、生成AI関連など）には根拠条文を明記する
